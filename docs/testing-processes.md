**Хранилища, Linux-образы Node 26 и телеметрия.** В PHP-образ включить `pdo_pgsql`, `ext-sodium` (для профилей сегментированного конвертного шифрования), `pcntl`, а для OpenTelemetry — `ext-opentelemetry >= 1.4.2` (`1.5.0`) + нативный `ext-protobuf` через **PIE** (`php/pie` или `install-php-extensions`, PECL устарел). Во все Linux-образы на базе **Node.js `>=26.13.1` LTS** (`hub`, `sheets-runtime`, `sheets-realtime`) **обязательно** устанавливать: на Debian/Ubuntu (`bookworm`/`trixie`, GCC >= 13.2) — `libatomic1`, на RHEL/AL2023 — `libatomic`, на **Alpine — `apk add --no-cache libatomic libstdc++`**, плюс шаг `RUN node -e "process.exit(0)"` в Dockerfile. Контейнерные образы подписываются по `@sha256` через **Sigstore `cosign >= 3.0.2`** (Docker Notary v1 отключается 08.12.2026). Для трассировки OpenTelemetry использовать асинхронный OTLP HTTP/protobuf на loopback sidecar Collector (встроенный батчинг экспортера, атрибуты `vaulter.*`, бюджет `< 2 мс` p95), передачу `traceparent` на каждую логическую WS-мутацию и Span Link в Outbox Relay ([engineering-standards.md](../engineering-standards.md#38-slo-бюджеты-производительности-и-opentelemetry-2026)). Для продакшен-SSE в облачных установках использовать `Centrifugo >= 6.9.0` (Apache-2.0) либо Octane (`^2.12.1`) с 25-секундным Bounded-Window SSE (`dunglas/mercure` и встроенный `minio/minio` запрещены по AGPL-3.0). Каталог Media `/app/storage/app` монтировать одним томом `media` в `owner-http` и процессы владельца, которые сохраняют/очищают блобы. Снимки, права, очередь, outbox, команды и квитанции сохраняет PostgreSQL (PgBouncer: `max_prepared_statements = 200`, `PDO::ATTR_EMULATE_PREPARES => false`). Кэш расчёта, временный каталог импорта и память Hub можно терять. XLSX в 4.3 — capability установленного адаптера Sheets. Для проверенной headless-конфигурации достаточно runtime (`child_process.fork`, `--max-old-space-size=640`, рестарт каждые 50 задач); внешний сервис конкретного конвертера добавляется отдельным профилем только при выборе требующего его адаптера. На стадии 0–5 отдельного сервиса синхронизации книг нет.

**Жизненный цикл команды книги.** У владельца одна точка проверки режима для браузера и агента: заблокированная запись `v_documents.write_mode`. Для `snapshot` подготовить кандидата через runtime и проверить текущий режим, generation, позицию, digest и полномочия до атомарного commit. Для `journal` передать ту же семантическую команду и тот же ключ в очередь авторитетной комнаты Sheets; дождаться подтверждения владельцем записи в журнал и связи с квитанцией. Потеря комнаты оставляет ожидающее намерение или явную временную ошибку. Обычный PUT или применение уже подготовленного снимка не может перезаписать журнал. Возобновление проходит по прежнему ключу. Отдельная snapshot-книга остаётся доступной при отказе realtime.

**Обмен файлами.** В 4.3 тестовый клиент отправляет задание на `POST /api/vaulter-sheets/v1/workbooks/{nodeId}/exchanges`. PHP проверяет права, закрепляет исходный блоб/версию, ключ намерения, сохраняет задание в `v_sheets_exchange_jobs` и ставит его в `sheets-exchange`. Worker с lease вызывает отдельный `POST /v1/exchange` у приватного runtime на 3100. Для импорта перепроверить доступ, режим и основу у владельца до записи. Для экспорта читать закреплённую версию и вернуть доступному субъекту ссылку на итоговый артефакт с перечнем потерь. Оригинал и старый снимок сохраняются при отказе конвертера. Тип файла (CSV, XLSX) должен быть разрешён профилем и покрыт отдельным корпусом. При выключенном профиле маршруты обмена не предоставляют услугу, очередь не потребляется. [Данные и повторы](../database/sheets.md)

**Очереди и время остановки.** У `sheets-worker` использовать `retry_after=75s` для его подключения Laravel database (`DB_QUEUE_RETRY_AFTER=75` в конфигурации процесса) и `stop_grace_period: 55s`. Конфигурация стенда: вызов runtime до 25s, timeout job 45s, lease 60s, возврат задачи в очередь через 75s. Инвариант проверяет владелец: worker с истёкшим или сменившимся токеном аренды не фиксирует результат. Обрыв после сохранения намерения, до enqueue, устраняет recovery. Процессы `agent-worker` и `projection-worker` используют 100s для своих очередей в той же БД.

**Сеть браузера.** `VAULTER_BACKEND_URL` Hub — DNS PHP внутри Compose; `VAULTER_COLLAB_URL` в PHP — WebSocket origin, разрешимый именно клиентом теста. Для `browser-test` в сети Compose использовать `http://owner-http:8000`, `ws://hub:1234`; для Playwright с машины — опубликованные loopback-порты обоих сервисов. Список разрешённых origin Hub соответствует странице в выбранном варианте. При HTTPS-странице нужен WSS. Management порт не публиковать. Для подписанного внутреннего `/control` по HTTP выбрать management-привязку внутри контейнерной сети. Room-JWT подписывается Laravel; ключи `VAULTER_COLLAB_JWT_KEYS` и `VAULTER_COLLAB_JWT_ACTIVE_KID` выдаются только PHP. У Hub и Laravel совпадает отдельный `VAULTER_COLLAB_WEBHOOK_SECRET`. [Конфигурация PHP](../../../packages/collaboration/config/vaulter-collaboration.php) · [Конфигурация Hub](../../../packages/collaboration/hub/src/config.js)

Сборку PHP-образа разделить на стадии `composer install --no-dev --prefer-dist` по lock-файлу, npm build для требуемого профиля и PHP runtime с `vendor/` и готовым `public/build/`. Для браузерного потребителя пакеты проверять через обычный registry или локальный tgz. Источники соседнего монорепозитория в `vendor/` и `node_modules/` не монтировать. Образ PHP без AI-профиля проходит проверку состава с отключёнными приватными registry. Доставку фонового задания имитирует доверенный Laravel worker; семь опубликованных инструментов модели принимают только аргументы Office. В тесте удалённого исполнения Python вообще не получает credentials PostgreSQL.

Формат входного `artifacts.json` для сборщика — объект версии 1. `composer` и `npm` содержат массивы `{name,version,path,sha256}`, `images` — массив `{service,reference}`. `path` — путь к готовому архиву относительно файла входа, `sha256` — 64 строчных hex-символа. Для локально собранного образа `reference` — неизменяемый image ID, для registry — полное имя с digest. Комбинация `(name,version)` уникальна в своём канале. `prepare` прекращает сборку при несовпадающем имени внутри архива, отсутствующей зависимости или контрольной сумме. Выходной `build.json` фиксирует выбранный профиль, версии пакетов/образов и фактические порты. Он не содержит ключи.

Контракт нового `stack.sh` ниже. Каждый вызов выполняется из `vaulter-ai/tests/consumers/office/`. На вход `artifacts.json` подать локальные пути к ZIP/tgz и ID/digest контейнерных образов соответствующих пакетов. В `prepare` сверить хеши, выбрать зависимости именно запрошенного профиля, сгенерировать отдельные Compose project name, секреты и непересекающиеся loopback-порты. Сохранить под `.fixture/<run-id>/` манифест сборки, сгенерированный env и защищённые файлы секретов. Единственная строка stdout `prepare` — идентификатор успешного запуска; диагностика направляется в stderr. В последующие команды передавать его явно. Возврат из `prepare` без успешных `composer validate`, `composer check-platform-reqs`, npm build и `docker compose config --quiet` означает ошибку.

```bash
run_id=$(./stack.sh prepare ai-sheets /absolute/path/to/artifacts.json)
./stack.sh up "$run_id"
./stack.sh test "$run_id"
./stack.sh restart "$run_id" sheets-runtime
./stack.sh test "$run_id" cold-reopen
./stack.sh down "$run_id"
```

`up` собирает выбранные образы, вызывает `docker compose up -d --wait postgres`, затем `docker compose run --rm migrate`. Только после успешной миграции запускает HTTP, настроенные workers, Hub и runtime. Сначала дождаться готовности PHP. Его общая readiness не зависит от Hub, чтобы Hub смог вызвать PHP на старте. Перед тестом живой записи дождаться readiness соответствующего Hub. `test` загружает известный исходник на пустом прогоне; повторные и аварийные шаги используют зафиксированный ID сценария и сохранённое состояние. `down` завершает процессы с заданным grace period и оставляет тома запуска для анализа. Отдельный `clean <run-id>` удаляет только проверенный Compose project и тома именно этого одноразового прогона.

Для существующих манифестов сегодня из корня Vaulter выполняются `docker compose -f e2e/docker-compose.yml config --services` и `docker compose -f packages/collaboration/hub/stand/docker-compose.yml config --services`. В первом результате четыре сервиса: postgres, laravel, hub, vite. Во втором пять: postgres, backend, redis, hub-a, hub-b. Проверено Docker Compose 5.6.1. Команды проверяют разрешение конфигурации. Запуск новых закрытых runtime и фазовые испытания оформляются отдельными результатами.

## Сбой и остановка

| Действие теста | Наблюдаемый результат |
| --- | --- |
| Остановить `agent-worker` после фиксации, до выдачи клиенту; затем запустить его заново | Worker восстанавливает задание по ключу, спрашивает status, не дублирует запись. Для `--timeout=75` выставить `retry_after=100` секунд и `stop_grace_period: 90s`. Отдельно прервать процесс SIGKILL и дождаться возврата job в очередь |
| Остановить PostgreSQL между prepare и commit | Владелец возвращает штатный временный отказ либо неизвестный клиенту исход при потере ответа. После восстановления status по прежнему ключу отличает committed от непринятого. Рост позиции соответствует единственной фиксации |
| Убить Hub сразу после записи журнала, до применения в живом Y.Doc | Новый Hub воспроизводит checkpoint и непрерывный хвост раньше следующей команды. Точный порядок, квитанция и эффекты сверяются с [A42](../../examples/live-write.json). Для штатного SIGTERM дать `stop_grace_period: 45s` при исходных пределах flush 30s + destroy 5s |
| Остановить Sheets runtime до ответа с кандидатом или после ответа до фиксации PHP | Специально задержать сравнение базовой версии у владельца. Изменившаяся книга либо пересматривается по устойчивым целям, либо отклоняется. Читатель не видит частично опубликованный снимок; повтор не создаёт лишней версии |
| Прервать owner после записи намерения/файла до enqueue. Отдельно убить `sheets-worker` после получения кандидата до commit. Возобновить процессы и вызвать `php artisan vaulter-sheets:recover` | После окончания прежней аренды новая попытка получает свой токен, открывает прежнюю запись и публикует один эффект. Проверить состояние команды и файла после повтора. При скрытом для субъекта ресурсе сохранённая квитанция или блоб не выдаются |
| Приостановить projection-worker, выполнить restore, доставить старую job | Предыдущее поколение не меняет новый индекс. После догоняющего чтения список и проверка после квитанции дают корректные значения или предусмотренный отказ об историческом доказательстве |
| Перезапустить PHP и перейти в другой browser context | Сервер проверяет пользователя заново. При потере прав не выдаются ранее доступные статус и diff. Артефакт аудита содержит времена, ID теста, поколения, позиции, коды ошибок и числа эффектов; секреты и полное содержимое исключаются |
